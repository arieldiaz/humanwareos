# Agent email Worker

Cloudflare Email Routing Worker that accepts the addresses in `ALLOWED_RECIPIENTS` and rejects raw MIME, including attachments, larger than the required `MAX_RAW_BYTES` (set it to the Email Routing limit, 25 MiB, unless the instance wants less). It writes the original MIME to the `EMAIL_RAW` R2 bucket binding under its SHA-256, then queues only bounded envelope metadata, `rawSha256`, `rawSize` and that same digest as the stable delivery ID on the `EMAIL_EVENTS` queue binding. The object is written before its pointer is queued; a failed write or send is not accepted, so the provider retries. MIME parsing, cryptographic sender authentication, attachments, calendar authorization and agent dispatch belong to the local trusted [email intake](../email-intake/README.md), which verifies the digest and size and deletes the object after committing it locally. Visible or forged authentication headers confer no authority. The Worker never sends automatic replies. `SERVICE_NAME` sets the name reported by `fetch` (default `agent-email`).

The Worker only produces queue messages and objects; the local intake pulls ingress and dead-letter messages and reads objects over authenticated outbound HTTPS (Cloudflare Queues HTTP pull and the R2 REST API). The bucket needs no public access, custom domain or lifecycle rule.

The instance owns `wrangler.jsonc` (worker name, addresses, queue names) with `main` pointing at this `src/index.js`. Test with `npm ci --ignore-scripts && npm test`.
