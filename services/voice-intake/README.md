# Voice capture intake

Loopback service that turns one owner recording into one agent turn in the instance's Slack intake thread. The contract is the capture intake section of [docs/voice-channel.md](docs/voice-channel.md). It has no npm dependencies and requires Node 22.13 or later for `node:sqlite`.

## Listeners

- Capture, `127.0.0.1:<capturePort>` (default 8800): `POST /capture` (multipart or urlencoded form) and `GET /health`. This is the only tunnel target. Form fields: `audio` (file) or `text` (dictation fallback), `deviceName`, `deviceModel`, `capturedAt` (ISO 8601), `shortcutVersion` (an integer; missing or unreadable means pre-v4 and never rejects), and optional `latitude`, `longitude`, `locationCity`, `locationState`, `locationName`. Location fields that are blank or unreadable are stored as absent and never reject a capture; the label is `City, State`, else whichever of city, state, or name exists. The multipart parser accepts any boundary, CRLF or LF framing, a missing closing delimiter, and RFC 5987 file names; size limits and the audio byte check still apply. Audio is then measured with ffmpeg (`-af volumedetect`): a peak below `audioGuard.minDb` (default -50 dBFS) is rejected as `silent_audio` ("Recording was silent: check the Mac's input device in System Settings → Sound") and a clip shorter than `audioGuard.minSeconds` (default 0.5) as `too_short`, before any evidence is written. If ffmpeg is missing or fails, the service logs `audio_guard_skipped` and accepts the capture. Responses are JSON with `status` (`accepted` 202, `duplicate` 200) or `error`, `captureId`, `requestId`, `shortcutVersion`, and a short `message` the Shortcut shows as a notification: `Sent ✓ · v4` from a current Shortcut, or `Sent ✓ · shortcut v3 is outdated, v4 is available` from an older one. Every rejection writes one JSON line to stderr with `requestId`, `status`, `reason`, `contentType`, and `contentLength`, never the body or Access headers.
- Audio, `127.0.0.1:<audioPort>` (default 8801): `GET /audio/<captureId>` with byte ranges, and `GET /health`. Route it only from the private domain, never from the tunnel.

Health fails while Slack verification fails or any capture is held.

## Configuration

Instance config is read from `$VOICE_INTAKE_CONFIG`, else `$HUMANWARE_RUNTIME_ROOT/config/services/voice-intake/config.json`. `config.example.json` documents every key: `agentId`, `slackChannel` (a name in `config/channels/slack.json` `registry`, default `inbox`), `timeZone`, `privateOrigin` and `audioPath` (together the audio link prefix), ports, `maxBytes`, `maxAttempts`, `transcriber` (whisper.cpp: `bin`, default `/opt/homebrew/bin/whisper-cli`; `model`, the path of a ggml model file, required; `language`; `ffmpeg`, used to decode the capture to 16 kHz mono; optional `threads`; `timeoutMs`), optional `audioGuard` (`ffmpeg`, default `/opt/homebrew/bin/ffmpeg`; `minSeconds`; `minDb`; `timeoutMs`), optional `summary` (loopback Ollama `url` and `model`; omit `model` to use the transcript's first words), and optional `dataDir` and `evidenceRoot`. The root posts as soon as transcription ends, titled with the transcript's first words; the summarizer then edits that title in place (`chat.update`, with the token that posted the root), so a slow or absent summarizer never delays the thread. A transcript under four words, or one of Whisper's stock silence outputs such as "Thank you." or "Thanks for watching.", skips the summarizer and is its own title. Each root logs one JSON line (`capture_rooted`) with `transcribeMs`, `rootMs`, and `sinceReceivedMs`, and each retitle logs `capture_retitled` with `summaryMs`.

Transcription runs whisper.cpp on Metal (`brew install whisper-cpp`), which maps the model from disk per call in well under a second on Apple silicon, so no model server stays resident. Run the service at normal scheduling priority: a LaunchAgent with `ProcessType` `Background` confines its children to efficiency cores and makes the same transcription several times slower.

Environment: `HUMANWARE_DATA_ROOT` (required), `HUMANWARE_RUNTIME_ROOT`, `VOICE_INTAKE_CONFIG`, `OPENCLAW_BIN` (default `openclaw`), `VOICE_INTAKE_SLACK_BOT_TOKEN`, the configured agent's bot token injected by the instance secret wrapper, and optional `VOICE_INTAKE_SLACK_USER_TOKEN`, an owner user token (`xoxp`) with only the `chat:write` user scope. When the user token is present the root post and transcript reply are posted as the owner; verification, channel reads, and reconciliation always use the bot token. Post metadata is attempted first and dropped for the rest of the process if Slack refuses it for the posting token; reconciliation then matches author and text. Without the user token the bot posts exactly as before. The root post never mentions the agent: the dispatch path already starts the turn.

Data: audio evidence `$HUMANWARE_DATA_ROOT/evidence/voice/captures/YYYY/MM/<id>.<ext>` plus `<id>.json` (including `shortcutVersion` and `location` with coordinates and label, or `null`); state `working/projects/voice-intake/captures.sqlite3`; request records `working/projects/voice-intake/requests/<id>/request.json`. Directories are 0700 and files 0600.

## Shortcut

```sh
node services/voice-intake/shortcut.mjs --url https://<ingress-host>/capture --out-dir <data-plane directory>
```

Writes `Voice Intake v<N>` (Record Audio, starts immediately, finishes on tap, then Get Current Location and Get Details of Locations inside an "if the location has any value" branch) and `Voice Intake (Dictation) v<N>` as unsigned `.unsigned.shortcut` files, then signs each with `shortcuts sign --mode people-who-know-me`. `N` is `SHORTCUT_VERSION` in `shortcut.mjs`, also written as the first action, a Comment reading `Voice Intake v<N> · built <date> · Humanware OS`, and sent as the `shortcutVersion` form field; the service records it in the ledger (`shortcut_version`) and evidence record, names it in the notification, and adds `Shortcut v3, current is v4` to the transcript reply only when a device runs an older build. Bump the constant whenever the generated actions change and record `shortcutDigest()` in `shortcut.fixture.json`; the test fails until both move together. Keep the imported Shortcut named `Voice Intake` so Action button and Watch assignments survive a reinstall. Location runs after the recording so it never delays it; a device without a fix uploads with blank location fields. Shortcuts has no error handling, so a denied location permission stops the run before upload: allow location for the shortcut on first run. Get Current Location is reported to fail on watchOS, so the dictation variant carries no location by default (`buildShortcut({mode: 'dictate', location: true})` adds it). Signing requires a macOS user signed in to iCloud; otherwise the command exits nonzero and leaves the unsigned files for a signed-in Mac. Stopping the capture sends it; there is no review menu, so the service's silence and length checks catch an accidental tap. The notification shows the service's `message`; a page titled Cloudflare Access shows "Blocked by Cloudflare: check token", and any other non-JSON reply shows "Mini unavailable". Import asks for the Access client ID and secret; neither is in the file. Write output to the data plane, never to Git.

## Operation

A held row records a bounded `reason`: `<state>_failed` after `maxAttempts`, `empty_transcript`, or `admission_unconfirmed`. Inspect the gateway run for `voice-intake:<captureId>` and the Slack thread before acting. A held capture before `posted` can be retried by setting `state` back to its prior value and `attempts` to 0; posts reconcile by metadata. Never reset an `admission_unconfirmed` row to `posted` without proving the turn did not run.

## Tests

```sh
node --test services/voice-intake/*.test.mjs
```

Tests use synthetic audio bytes with mocked whisper-cli and ffmpeg binaries, summarizer, Slack, and gateway. They do not prove the edge tunnel, Access policy, Shortcut import, or live Slack delivery.
