# Session Console and Activity

The [traceable activity contract](docs/traceable-activity-index-spec.md) owns the envelope. The builder copies OpenClaw's sanitized SQLite trajectory into Humanware evidence, appends a separate metadata projection to the canonical session ledger, and builds the session feed and Activity index. No new daemon, permission evaluator, memory writer, or platform store is introduced. Runtime assembly already includes this directory and the domain surfaces.

## Producer and projection paths

- `evidence/sessions/events/YYYY-MM-DD.jsonl`: append-only events, independent of display level.
- `evidence/sessions/raw/openclaw/YYYY-MM-DD.jsonl`: append-only sanitized provider-visible activity, including messages and tool calls/results but never hidden chain-of-thought.
- `evidence/memory/events/`: normalized memory-service events alongside historical evidence. Untyped historical memory contributes to the coverage gap, never inferred lineage.
- `generated/sessions/current.json`: recent session events including memory events, with truncation indicated.
- `generated/sessions/records/*.json`: one private file per session, with summary first and the complete captured activity second.
- `generated/sessions/summaries/*.md`: one metadata-only Markdown summary per session for linked read-only projections.
- `generated/indexes/activity/index.sqlite`: one disposable SQLite store, day-partitioned through `(day,id)` keys and indexed across dates by actor, session/run, and target.
- `generated/indexes/activity/current.json` and `days/*.json`: metadata manifest and content-addressed static exports of that store. Old partition exports remain readable for in-flight clients; removing the entire generated Activity directory and rebuilding is safe while the surface is offline.

Other trusted host adapters call `activity.emit(data_root, **fields)` or construct `activity.event(...)` and use `append_events`. Supply stable IDs from observed source records, an actor/profile, UTC timestamp, session/run, and typed source references. Parent IDs are observed causal edges, not chronological guesses. The helper constructs a closed metadata envelope; arbitrary dictionaries, summaries, commands, outputs, prompts, and memory text are excluded. This API must never be registered as a model-callable self-report tool. Memory producers keep claim IDs and introduction/membership snapshots with the claim in their own projections.

The OpenClaw adapter translates tool calls/results, context compilation, model invocation, explicit host context/memory events, the gateway's sub-agent run registry, and transcript usage. Each registry run yields one `run.spawned` and, once ended, one `run.completed` with status and duration. Brief and result text never enter the ledger. It never derives grants from prompts or success from response prose. Existing records without observed run/profile/policy/context membership remain unknown.

## Cost

Code computes cost from observed tokens; the host's own estimate is not used. The host transcript is the usage source only where a record holds a whole run's count, and then each such assistant record yields one `usage.cost` holding the four token classes and the model, and no amount. A run is one unit: a harness run writes many assistant records and at most the last carries tokens, which sum the run's model calls when the host observed each call and only the last call when it fell back. A count is the whole run when the run made one model call, or when its prompt tokens (input plus cache) exceed the context figure the record reports; otherwise it covers one call of several. A run whose records hold no whole count, such as a run with no token record or a last-call fallback, yields one `usage.cost` without tokens, unavailable, with an event ID stable per session and run. A CLI-harness turn (`api` of `cli`) holds roughly one call of the turn, so the host transcript is not its usage source. For the Claude Code CLI the CLI's own call log is: the builder reads `<claude root>/projects/<directory>/<CLI session id>.jsonl` and the session's `subagents/*.jsonl` files (`--claude-root`, default `$CLAUDE_CONFIG_DIR` or `~/.claude`; a missing directory prices nothing), finds the CLI session id on the live host session entry (`cliSessionBindings`), and sums the calls made after the session's previous CLI turn up to this turn's record, counting each call once at its last streamed line and ignoring synthetic lines. That sum is reported with the five token classes under the turn's own event ID, one more report per other model in the window; the builder keeps each session's last CLI turn time in its usage cache. A CLI turn with no live binding, no log, no call in its window or a call whose counts are unusable is reported without tokens, unavailable, and nothing is guessed. A session the host already deleted or reset has no binding, and a log past the CLI's retention (about 30 days) is gone, so those turns cannot be recovered; a re-read of a turn already reported adds nothing. A record without a run id is one call: with tokens it is reported as above, without them it is unavailable, and such records of one session share one report (`uncounted`) because they say nothing about their calls. Records from the `openclaw` provider are delivery mirrors, not model calls, and yield nothing. Each scheduled build reads the records added since the last one, with the row before each as context, and a deleted or reset session's records come from the host's transcript archive under the same event IDs. Trajectories and session counters are not usage sources; the counters describe a session's last call.

`pricing.py` prices a report when it is read, from `model-prices.json`: public list prices per million tokens for each token class and model, each row with an effective date, an optional last day (`effectiveUntil`, inclusive) and its source. The row in effect on the usage date applies, and the amount cites it as a `rate` reference. `cacheWrite` is the 5-minute cache write price; a report with 1-hour writes (`cacheWrite1h`, the CLI log's split) is priced at the row's `cacheWrite1h` rate, and is unavailable for a row without one. The amount is an **API list-price equivalent**, not a bill, because several harnesses run on subscriptions; every surface that shows it says so. A report without tokens, with a missing token class, an unpriced model, or a date outside every row's dates stays unavailable, so usage after a row's last day stays unavailable until a published row is added. Nothing is estimated. Because evidence stores no price, a corrected or added row reprices history on the next build without new events. The table sits beside its only reader and in the framework, since list prices are public; an instance supplies nothing.

One usage is counted once. The latest report per `usageId` replaces earlier ones, attributed to its first observed day. A run total on `run.completed` counts only when its child session has no invocation report. A report with neither amount nor model yields to reports from the same session that name one. A report without tokens yields to a report with tokens for the same session and run, so a run first seen without a count and counted in a later build is priced once. A report that does not yield and has no amount is counted as unavailable in every total. A run's tokens and cost are its child session's reports; runs that share a session split them by start time. Each session in the feed carries `cost`: the total in `amount`, `root` and `workers` subtotals, and `byModel`, `byDay` (UTC) and `byRun`, each with report and unavailable counts. The generated conversation summary reads `cost.amount` and `workerRuns`.

Version 1/2 evidence remains unchanged. New indexed activity uses version 3. The builder reconstructs historical event metadata and never copies raw titles, commands, excerpts, or reasoning into the cross-session Activity feed. Full sanitized activity remains available only in the local session record. There is deliberately no browser endpoint for Tier 0 raw payloads.

## Rebuild

Rebuild from evidence alone with the runtime's `activity.py --data-root` command. The data-root argument is the absolute instance-selected data root. This requires only Python's standard library. Normal scheduled session-console builds also rebuild Activity. Invalid evidence and conflicting IDs abort publication; the previous feed remains available and becomes visibly stale. No production schema migration or ledger rewrite is needed. Rebuild cost is linear in retained evidence; this initial slice does not implement incremental indexing.

## Private surfaces

The template route manifest declares private `/activity/` and `/sessions/` routes. The deployment adapter must serve their framework assets, map `/activity/data.json` to the Activity manifest, `/activity/days/*` to the exported partitions, and `/sessions/data.json` to the existing session feed. Apply the same network and identity gate to HTML, scripts and JSON; never expose the SQLite file, evidence directories, or data-root directory listings. These are instance deployment bindings, not a new standalone server.

Activity searches dates, identity, kind, target, reversibility and channel. It shows separate exact/estimated subtotals and missing-report counts by identity/profile/day/currency. Spend uses date and identity filters only; lineage shows the latest observed membership across all dates. Sessions renders the same metadata trace by run with the session's cost by worker run, model, day and root run, linking truncated history to Activity. Freshness uses the generation time (stale after two minutes); source coverage is separate and does not claim unobserved actions.

The framework Sessions page at `surfaces/domain/sessions/` serves the established `/sessions/` route: a live session list with status filters and a detail drawer that renders the shared `/activity/trace.js` trace by run and honors `?session=` and `?run=` links. Add the Activity route and data bindings through the existing instance manifest/deployment review.

## Verification and remaining acceptance

Python tests exercise synthetic two-identity causal traces, multi-day queries, idempotent emission/rebuild, memory membership, malformed evidence, cost states, list pricing and date-effective rates, roll-ups, single counting of usage, capture across child cleanup, partial source writes, and payload exclusion from the SQLite store and both web feeds. Node tests cover filters, escaping, freshness, navigation, and trace rendering. JSON Schema validation is a test-only dependency; production uses the closed metadata helper and standard-library SQLite.

Live coverage on each enabled harness, actual provider reconciliation, instance-overlay adoption, and unauthorized-client rejection require separately reviewed instance integration and deployment. This slice does not claim universal harness instrumentation or retroactive lineage for prose-only memory. There is no merge, restart, or deployment authorization in implementation approval.
